# Соответствие PDF

Базовый путь `/api/v1`, Swagger `/api/v1/docs`.

| Пункт задания | Метод и путь |
| --- | --- |
| 1.1 Все тарифы | GET `/tarifs` |
| 1.2 Тариф клиента | GET `/tarifs/by-client/{phone}` |
| 1.3 Количество клиентов на каждом тарифе | GET `/tarifs/stats/client-count` |
| 1.4 Количество на заданном тарифе | GET `/tarifs/{id}/client-count` |
| 1.5 Обновить тариф | PUT `/tarifs/{id}` |
| 1.6 Создать тариф | POST `/tarifs` |
| 1.7 Удалить тариф | DELETE `/tarifs/{id_tarif}` |
| 1.8 Тарифы с количеством клиентов | GET `/tarifs/with-client-count` |
| 2.1 Поиск по началу телефона | GET `/clients/search/phone?phone=%2B7` |
| 2.2 ФИО и дата рождения по возрастанию | GET `/clients/sorted-by-birthday` |
| 2.3 Паспорт выдан после года | GET `/clients/search/passport-year?year=2015` |
| 2.4 Тариф дороже суммы | GET `/clients/search/tarif-cost?minSalary=300` |
| 2.5 Изменить клиента | PUT `/clients/{phone}` |
| 2.6 Удалить клиента | DELETE `/clients/{phone}` |
| 2.7 Назначить тариф | PATCH `/clients/tarif?phone=%2B79001234567&id_tarif=1` |
| Список клиентов с тарифами (первая страница PDF) | GET `/clients/with-tarif` |

## Уточнения к условиям

- В пункте 2.7 лишний `/` исправлен; оба аргумента — query-параметры, как в URL из PDF.
- Удаление тарифа выполняется по `id_tarif`, согласно пути в пункте 1.7.
- Для списка клиентов с тарифами URL в PDF не задан; выбран `/clients/with-tarif`.
- Поле имени — `firstname`, как в текстовой структуре и JSON PDF.
- Номер телефона — первичный ключ, выбирает клиента в PUT/DELETE; в теле PUT его нет.
- PUT обновляет переданные поля; пример для клиента: `{"lastname": "Петров"}`.
- После 2015 года означает начиная с 2016-01-01; стоимость сравнивается строго `>`.
- Клиенты с тарифами возвращаются с вложенным объектом `tarif` через SQL LEFT JOIN.
- Тарифы без клиентов входят в статистику с количеством 0.
- Деньги хранятся как `NUMERIC(12, 2)`, паспортные реквизиты — строки с сохранением нулей.
- У клиента может отсутствовать тариф (`id_tarif: null`), отчество также допускает null.
- Тариф с клиентами удалить нельзя (409); сначала смените тариф или удалите клиентов.
- Создание тарифа — 201; удаление — 204 без тела; отсутствие записи — 404;
  неверный запрос — 422; конфликт связи — 409. Ошибки транзакций откатываются.

## Файлы приложения

`app/entities.py` — две таблицы и схемы запросов/ответов.
`app/database.py` — подключение, создание таблиц и сессии.
`app/operations.py` — запросы к БД.
`app/routes.py` — ровно 16 HTTP-операций задания.
`app/main.py` — приложение и запуск.

## Проверка

Из `fastapi_project`, в установленном виртуальном окружении:

```bash
python -m pip install -r requirements-test.txt
python -m pytest tests -q
```

По умолчанию используется временная SQLite с внешними ключами.
Для PostgreSQL укажите `TEST_DATABASE_URL` на отдельную БД с окончанием `_test`:

```powershell
$env:TEST_DATABASE_URL="postgresql+psycopg://DB_USER:DB_PASSWORD@localhost:5432/telecom_test"
python -m pytest tests -q
```

Тесты создают и удаляют только собственные временные схемы в тестовой базе.
Проверяются точный набор операций, формы ответов, SQL JOIN, счётчики,
границы фильтров, изменения, ошибки и неизменность данных после повторных GET.
