# Проверка параметров заказа

Учебный проект на Python 3.10+: проверка идентификатора товара и количества,
параметризованные unit-тесты pytest, граничные значения и попарное тестирование.

## Правила

- `is_valid_id(product_id: str) -> bool`: строка из **1–4 уникальных букв A–Z**.
  Регистр важен. Цифры, кириллица, пробелы, повторы и другие типы запрещены.
- `is_valid_quantity(quantity: str) -> bool`: положительное целое количество.
  Принимается строка из цифр `0–9` либо положительный `int` из JSON.
  `None`, `bool`, `float` (даже `1.0`), дроби, пустые строки и текст запрещены.
- `check_params(product_id: str, quantity: str) -> str`: возвращает
  `Корректно`, только если оба параметра верны; иначе `Некорректно`.

Уточнения для случаев, не определённых явно в условии: ведущие нули допустимы
(`"001"` = положительное количество), знак `+`, пробелы, Unicode-цифры и
экспоненциальная запись запрещены. Верхнего предела количества нет:
`9999999999` в PDF — пример большого числа, а не установленный максимум.
Ввод не обрезается и не преобразуется молча. Некорректные типы возвращают
`False`, а не вызывают исключение. Отмена консольного ввода обрабатывается
через `EOFError` и `KeyboardInterrupt`.

Функции доступны напрямую и как статические методы `CheckData`, как в PDF:

```python
from app.utils.check_data import CheckData, check_params

assert CheckData.is_valid_id("ZOMX") is True
assert CheckData.is_valid_quantity("10") is True
assert check_params("A", "10") == "Корректно"
assert check_params("AA", "10") == "Некорректно"
```

В PDF есть неточности: `None` в смешанном регистре не соответствует правилу
заглавных букв, а в таблице попарных тестов перепутаны описания ошибок.
Реализация следует правилам валидации и результатам приложенных JSON.
Строка `"TRUE"` допустима как ID, объект `True` — нет.

## Запуск на Windows (PowerShell или терминал VS Code)

Установите Python 3.10 или новее. Распакуйте архив и откройте терминал
**внутри папки `order_project`**, где лежит `requirements.txt`.

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pytest -v
.\.venv\Scripts\python.exe -m app.main
```

Активация окружения не требуется, поэтому менять ExecutionPolicy не нужно.
Если команда `py` не найдена, после установки Python откройте новый терминал;
если доступна команда `python`, используйте её вместо `py` в первой строке.

Пример работы программы:

```text
Идентификатор товара: A
Количество товара: 10
Корректно
```

## Что проверяют тесты

`TestCheckData` содержит три параметризованных метода: проверку ID,
проверку количества и совместную проверку. Ожидаемые результаты заданы
в тестовых данных независимо от реализации валидаторов.

| Параметр | Классы эквивалентности и границы |
| --- | --- |
| ID | Длины 0, 1, 2, 3, 4, 5; повторы; нижний/смешанный регистр; кириллица; цифры; спецсимволы; пробелы; неверные типы |
| Количество | −1, 0, 1; большие числа; дроби; пустота; текст; пробелы; знаки; Unicode-цифры; bool; None |

Всего **44 случая в трёх основных тестах**: 14 для ID, 16 для количества,
14 для совместной проверки. Все 22 примера JSON включены в эти тесты;
отдельных тестов и фикстур для JSON нет. Внутри каждого теста входы уникальны.
Число `1` и строка `"1"` проверяют разные типы данных.

Попарная модель: два фактора (валидность ID и количества), по два уровня.
Проверяются все четыре пары:

| ID | Количество | Пример | Результат |
| --- | --- | --- | --- |
| Верный | Верное | `"A", 10` | Корректно |
| Верный | Неверное | `"A", 0` | Некорректно |
| Неверный | Верное | `"AA", 40` | Некорректно |
| Неверный | Неверное | `"AA", 0` | Некорректно |

Остальные совместные случаи проверяют исходные примеры и границы.
Это покрытие пар валидности, а не всех сочетаний подробных классов ошибок.

## Как устроена реализация

Правила собраны в статических методах `CheckData`. `re.fullmatch` проверяет
всю строку: `[A-Z]{1,4}` задаёт алфавит и длину ID, а множество проверяет
отсутствие повторов. Для количества шаблон `0*[1-9][0-9]*` разрешает ведущие
нули, но требует хотя бы одну ненулевую цифру. Числа из JSON проверяются
отдельно; `bool` исключается до проверки `int`, поскольку в Python это его
подкласс. Совместная проверка объединяет два результата через `all`.
Функции уровня модуля ссылаются на те же методы класса.
